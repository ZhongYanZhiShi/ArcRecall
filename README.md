# ArcRecall

ArcRecall 是一款本地归档处理工具，支持识别真实文件格式、生成正确后缀副本和递归解压嵌套压缩包。解密依赖已知密码和字典中的候选密码，当前以字典验证为核心，未来也不会添加暴力破解等穷举功能。

## 下载与使用

在 [GitHub Releases](https://github.com/ZhongYanZhiShi/ArcRecall/releases) 选择 Windows x64 安装包。macOS / Linux 暂无经过验证的发行包。

| 版本   | 文件名                                 | 适用情况                                                       |
| ------ | -------------------------------------- | -------------------------------------------------------------- |
| 基础版 | `ArcRecall_版本号_x64-basic-setup.exe` | 不附带离线引擎资源，适合已安装完整版或已自行配置引擎的用户升级 |
| 完整版 | `ArcRecall_版本号_x64-full-setup.exe`  | 附带完整离线引擎资源，适合首次安装、离线使用或补充资源         |

两版的应用功能相同。安装器会沿用已有安装目录并覆盖更新程序，保留已部署的引擎、离线资源、设置、字典和历史数据，无需先卸载。应用内更新使用基础版，减少重复下载；需要补充或更新引擎资源时，可安装同版本完整版，再进行离线部署。首次安装建议选择完整版。

1. 完整引擎版已内置离线资源。打开「设置 → 解密引擎」，若显示「待部署」，点击「离线部署」；确认引擎就绪，无 GPU 时可选「仅 CPU」。
2. 如需通过字典恢复密码，先在「字典」页面导入候选密码文件或手动添加候选密码。
3. 拖入压缩包，填写已知密码（如有），点击「开始恢复并解压」。
4. 完成后打开输出目录；未完成的归档可加入重试队列。

## 功能

- 按文件内容识别格式，创建正确后缀的副本，不修改原文件。
- 递归解压嵌套归档，在本机验证已知密码或通过字典恢复密码。
- 批量处理文件，支持取消、重试和可选的任务队列记忆。
- 保存恢复历史，导出 JSON / CSV 报告，统一备份字典、历史、预设、任务记录与通用设置。
- 创建 7z / ZIP 压缩包，可设置密码。
- 保存压缩预设和命名规则，从任务记录恢复压缩草稿并重新压缩。
- 只读预览归档目录，按路径搜索文件，查看声明大小与加密标记。
- 按分组管理候选字典，为单个任务或批次指定字典范围。
- 保存和应用处理预设；扫描文件夹并确认导入归档，自动合并分卷组。
- 批量检查归档完整性，重查未通过项并导出报告；调整队列顺序、批量应用预设或在当前项完成后暂停。
- 在「历史 → 任务记录」按类型查看解压、压缩和完整性检查结果，补充密码、调整字典或输出位置后加入重试队列。

归档预览不解压文件，也不展开嵌套压缩包。目录加密时，先在解压页的已知密码栏填写密码，再点击「预览内容」。为控制内存与界面开销，最多展示前 5000 项，并分页浏览；超出部分不参与路径搜索，目录输出超过读取上限时会明确提示。

在预览面板中勾选文件或目录，点击「提取所选」并选择输出父目录，会在其中新建 `ArcRecall-selected-*` 文件夹，保留归档内部路径；选择目录包含其全部子条目。支持选择筛选结果、清空选择与取消操作，失败或取消时清理本次未完成输出。超过 5000 项或包含链接、不安全路径、重名路径的归档暂不支持选择性解压，可使用原有整包流程。此操作使用已知密码，不搜索字典，不递归解压或整理层级，暂不写入恢复任务历史。

点击「检查完整性」会使用 7-Zip 校验整包内容，不向输出目录解压文件；加密内容需要正确的已知密码。检查通过表示当前归档条目可读取，不代表内部嵌套归档也已校验。错误密码、缺卷或数据损坏均会明确显示检查未通过，可取消正在进行的检查。分卷或 LZ4 包装可能在应用临时目录中准备副本，结束后清理。

字典默认使用「全部字典」。在字典页创建分组后，选中分组再添加或导入候选即可自动归组；也可勾选已有候选并通过「管理分组」加入其他分组。同一候选可以属于多个分组，移出或删除分组不会删除候选本身。解压选项中的「候选字典范围」只限制字典验证，已知密码和本机历史密码仍会优先尝试。分组随字典数据库备份、恢复；恢复旧版备份时不保留原分组。已删除分组的任务会提示重新选择，不自动改用全部字典。

任务记录自动保存解压恢复、压缩、选择性解压、单次完整性检查和批量完整性检查的路径、结果、耗时；批量记录还包含逐项结果与检查时间。支持类型筛选、未完成筛选、分页、打开输出和删除记录。记录不保存密码、实时候选或原始引擎消息。正常结束、取消、启动检查失败和意外中断均可查看；旧任务不会自动补录，旧恢复记录兼容显示。记录保存在应用数据目录的 `task-records.db` 并纳入统一备份。解压恢复重试需手动加入并启动队列；选择性解压和检查可补充密码后重新执行，也可停止当前操作。源文件会重新校验，输出重名时另建目录，不恢复引擎进度。检查结论只代表对应时间的检查，不展开嵌套归档。

在「设置 → 数据」创建 `.arcrecall` 统一备份，包含候选字典、分组、密码恢复历史、处理预设、任务记录，以及自动更新、日志和解压设置。待处理队列、引擎路径、AI 配置与密钥、压缩默认密码和 AI 命名偏好不在备份内。含历史密码的备份仍需原 Windows 账户解密。恢复前显示各类数据数量，确认后替换对应数据，并自动保存完整安全备份；发生错误时回滚，恢复过程中退出应用会在下次启动时回滚。旧 `.db` 备份只替换字典与历史，保留当前预设、记录和设置。预览后恢复固定快照，不受原备份文件后续变化影响；恢复的运行中记录标为中断，任务不会自动启动。

任务记录支持按文件名／路径关键词、任务类型、状态和本地日期范围组合查询，查询条件在分页前应用。点击「查询记录」应用关键词、状态和日期；导出使用已应用的筛选条件，包含全部匹配记录而非当前页，单次最多 10000 条、64 MiB。JSON／CSV 默认移除路径和字典分组，可勾选包含路径；不导出密码。可选择本页或逐条勾选，经确认批量删除，保留运行中的任务及所有源文件／输出文件。历史批量检查可仅重查未通过项，新检查独立生成记录。

在「设置 → 数据 → 自动备份管理」选择本机目录、每天／每周频率和 1–100 份保留数量后保存；默认关闭。应用运行时每分钟检查，到期后等待归档、导入等任务空闲；关闭期间不会唤醒系统，下次启动时补做。失败显示最近错误，至少 5 分钟后重试，不清理旧备份；成功后才执行保留策略。清理仅作用于当前配置目录中本机登记且内容未改变的自动备份，手动备份、恢复前安全备份及其他文件不受影响，切换目录不会清理旧目录。列表支持刷新、定位文件和预览恢复。「按已保存设置立即备份」也会执行保留策略。调度配置、最近状态和自动备份登记保存在本机 `backup-management.db`，不随统一备份迁移。

压缩页的「压缩预设」可保存格式、压缩级别、文件名加密开关、输出目录、完成后打开选项及命名规则，最多 100 个。命名规则支持 `{name}`（当前归档名称，未填写时取首个来源名称）与 `{date}`（本地日期），不填写扩展名。支持确认覆盖和删除；不保存来源、密码、永久密码引用或 AI 配置。应用前检查输出目录，失效时提示重新配置。

在任务记录中点击「准备重新压缩」，确认后替换当前压缩草稿并打开压缩页，不自动执行。记录保存源路径、格式、级别、名称、输出位置和文件名加密选项；加密任务只记录需要密码的提示，重试时重新输入并确认密码，不自动使用永久密码。缺失来源会提示移除并重新添加，失效输出目录需重新选择；执行时再次验证，输出重名时创建新归档，保留原输出。旧记录没有参数时不能自动恢复草稿。重试默认关闭 AI 命名和完成后打开目录。

新建统一备份使用版本 2，包含压缩预设；恢复版本 1 或旧 `.db` 备份保留当前压缩预设。恢复预览显示压缩预设数量，安全备份和自动备份也包含它们。压缩预设保存在 `compression-presets.db`；自动备份调度配置仍仅保存在本机。

支持 7z、ZIP / ZIP64、RAR3 / RAR5 的识别、密码验证与递归解压，具体限制如下：

| 格式        | 分卷支持与限制                             |
| ----------- | ------------------------------------------ |
| 7z          | 支持连续数字分卷                           |
| ZIP / ZIP64 | 支持 `.z01 … .zip`、`.zip.001 …` 分卷      |
| RAR3 / RAR5 | 加密形式受引擎支持限制，多分卷支持尚不完整 |
| LZ4 Frame   | 仅展开内部受支持的归档                     |

分卷归档需提供完整卷组；暂不支持创建分卷压缩包。密码恢复不保证成功，GPU 恢复需要可用的 Hashcat 设备。

恢复过程中会显示当前字典进度：7-Zip 显示正在测试的候选序号与已检查数量；John 显示引擎返回的百分比和候选范围；Hashcat 显示计算进度、速度和预计剩余时间。候选内容默认隐藏，可点击眼睛图标查看，仅保留在当前任务状态中，不写入事件、日志或导出报告。并行引擎的批次进度不代表单条候选序号。

嵌套扫描默认跳过直属文件超过 10 个的目录及其子目录，可在「设置 → 解密引擎」调整，或在当前会话的最近任务结果中补扫。

解压成功后默认从内向外清理本次产生的多层空文件夹，可在「设置 → 解密引擎 → 智能清理空文件夹」关闭。只用非递归的空目录删除操作，保留每个归档的输出根目录、解压前已有的目录、目录链接、带 NTFS 附加数据流的目录以及含任何文件（包括隐藏文件和零字节文件）的目录，不移动文件或合并层级。任务结果显示本次清理数量；无法可靠检查、无法删除或取消时未完成清理的目录会保留。

同一区域的「去除多层无效嵌套」默认开启，与空文件夹清理一起自动处理。仅识别本次新建解压目录顶部连续至少两层、名称与压缩包去掉最后一个扩展名后完全一致的单子目录，并保留一层原名。例如 `资料.zip` 中的 `输出/资料/资料/照片/2026` 整理为 `输出/资料/照片/2026`；`src.zip` 中的 `src/main/java`、日期和章节层级保持原样。遇到不同名称、同级文件或分支即停止，不猜测近似名称；纯空目录链交由空文件夹开关处理。已有输出目录、含链接或 NTFS 目录附加数据的目录树保持原样。整理在嵌套归档扫描前完成，不覆盖同名目标，移动后重新检查结构；失败时尝试回退，无法回退时保留完整内容并在任务详情中给出保留目录。两个开关可独立设置并保存。重复同名也可能具有业务意义，程序不能判断其语义；需严格保留所有原始路径时请关闭层级整理。

解压页的「处理预设」可保存当前输出位置、字典分组、递归开关、计算模式和完成后打开目录选项，最多 100 个。支持应用、删除和确认覆盖同名预设；不保存密码。应用前会检查引用的分组和输出目录是否仍存在，不自动替换失效配置。预设影响当前选项与后续导入，不改写已有任务的专用选项；保存在应用数据目录的 `processing-presets.db`，包含在统一数据备份中。

「扫描文件夹」按内容识别归档，可选择是否扫描子文件夹，能识别伪装后缀并将同一分卷组归为一个条目。扫描跳过符号链接和目录联接，不解压、不验证整包完整性；损坏或无法访问的候选会显示说明。结果支持按路径筛选、勾选与分页；确认后按当前处理选项加入队列，不自动开始执行，也不重置已在队列中的归档或分卷组。扫描最多检查 20000 项、收集 1000 个归档并深入 32 层子目录，最多展示 100 条问题说明；达到上限或停止扫描时显示部分结果。队列仍保持每批最多 200 个归档，请按需筛选并分批导入。

扫描结果或批次队列中勾选归档后，可打开「批量检查完整性」。每批最多 200 项，按顺序检查，单项未通过仍继续；支持取消并保留已完成结果、补充正确密码后仅重查未通过项，以及只选择通过项继续导入。重查保留本批其他条目的结果和检查时间；分卷归为一个条目。检查使用本次输入的密码，不搜索字典，结束后清空输入。结果只代表检查时的文件状态，不单独检查内部嵌套归档，不代表文件此后未变化。可导出 JSON / CSV 报告，默认不包含路径；结果仅在当前会话保留，开始下一批检查会替换后端结果，请及时导出。

队列空闲或暂停时，可上移、下移等待项，批量移除所选项，或为选中的等待项应用处理预设。应用前校验预设的分组与输出目录，保留会话密码，并按新预设重新计算输出位置。运行时点击「当前项完成后暂停」会让当前归档正常结束，再保留剩余等待项；可取消暂停安排或点击「继续处理」。原有「停止批次」仍会取消当前任务。启用任务队列记忆后，顺序与处理选项会保存，重启后需手动开始；不保存密码或引擎运行进度。

## 本地开发

需要稳定版 Rust、Node.js 22.12+（22.x）或 24+、pnpm 10+、mise，以及 [Tauri 平台依赖](https://v2.tauri.app/start/prerequisites/)。固定工具版本见 [mise.toml](./mise.toml)。

```powershell
git clone https://github.com/ZhongYanZhiShi/ArcRecall.git
cd ArcRecall
mise install
pnpm install
pnpm dev
```

构建完整引擎版：

```powershell
pnpm desktop:build
```

构建基础版使用 `pnpm desktop:build:basic`。本机签名打包使用 `pnpm package`，同时生成两版 EXE、各自的 `.sig` 和指向基础版的 `latest.json`，输出到 `artifacts/package-v版本号-*`。

`pnpm dev` 会启动桌面客户端。浏览器预览使用 `pnpm dev:web`，仅用于界面开发，文件处理需使用桌面版。项目结构与开发检查见[贡献指南](./CONTRIBUTING.md)。
